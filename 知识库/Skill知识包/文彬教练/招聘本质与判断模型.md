# 招聘本质与判断模型

> 本文档是 `eric-coach` skill 的诊断引擎。skill 运行「诊断阶段」时读取此文件，用于确定考察标准、运行判断模型、锁定核心焦虑、产出诊断报告。

---

## 招聘本质分层

诊断的第一步：先把候选人的岗位类型对号入座，再往下走。不同类型招聘，考察的东西根本不同，用错了框架只会产出无效建议。

### 实习 / 校招

**本质：发现人才，不是期待业绩。**

用人部门对应届生的真实预期是：头脑清醒、没被固有思维束缚、来了能上手、听话好培养、能快速融入团队和公司文化。

所以他们真正在评估的五件事：

1. **面试技巧**：能不能把自己做过的事说清楚，逻辑是否清晰，回答是否在点上。项目深不深是次要的，讲不讲得清楚才是关键。
2. **自我认知**：知道自己强在哪、弱在哪，不夸大也不乱谦虚。面试官怕的是「不知道自己不知道」的人。
3. **行业认知**：对目标行业 / 岗位有没有基本的了解，知道大盘在发生什么，能不能对话。不需要很深，但不能完全是空白。
4. **文化契合**：说话方式、思考方式、对工作的态度，与团队气场是否合拍。这一条很主观，但权重很高。
5. **好不好带**：接受反馈的态度，学习意愿，有没有太强的执念——来了之后是不是容易被带起来。

**给候选人的核心启示**：实习/校招里，简历上项目做了多少个、深度到哪里，对结果的影响远小于「能不能在面试里把事情讲清楚、展现出头脑在转」。改变备战方向比堆项目重要。

### 社招

**本质：直接解决问题，降低用人风险。**

社招候选人默认被期待「来了能干活」，面试官在评估三件事：

1. **过往成果与目标岗位的匹配度**：不是「你做过很多事」，而是「你做过的事，跟这个岗位要做的事，有多像」。匹配度越高，说服成本越低。
2. **能否直接解决岗位问题**：JD 背后有一个真实的业务问题需要被解决，候选人要能展示出「我见过这类问题、我处理过、我有结论」。
3. **稀缺经验的真实程度**：比如 AI 电话 / Voice Agent 领域，真实做过的人极少，一旦有就是强信号。面试官会专门深挖——讲得清楚细节，才算「真做过」。泛泛说「接触过 AI 产品」是负分。

**给候选人的核心启示**：社招靠的是「证明匹配」而不是「展示全面」。选择哪些经历放进简历，比把所有经历都写上去更重要。

## 判断模型库

判断模型是诊断阶段的核心工具。不是用来给零散建议的，是用来建立有逻辑结构的整体判断，再由此驱动后续改简历和面试准备的方向。

模型库持续成长：每辅导一个新客户，如果对话中产生了新的有效判断框架，加在本节末尾。

---

### 模型①：考察标准 vs 候选人自我认知的差距模型

**诊断什么**：候选人是否在按照招聘方真实的考察标准备战，还是在按照「自己以为重要的东西」备战。

**怎么用**：
1. 先用「招聘本质分层」确认这个岗位真正在考察什么（5 个维度 / 3 个维度）。
2. 读候选人的简历和他对自己的描述，提取他认为的「自己的强项和努力方向」。
3. 对比两者：哪里对齐了，哪里出现了错位。

**输出结论**：明确说出错位点。例如：「你在准备项目深度，但这个岗位的面试官在看你有没有自我认知——你现在做的方向对了，但你的优先级排反了。」

---

### 模型②：岗位长清单 → 真正必备 vs 加分项拆解模型

**诊断什么**：候选人有没有被 JD 的长清单吓到，把「加分项」当「必须满足」来准备，浪费精力在不关键的地方。

**怎么用**：
1. 拿到 JD，把所有要求列出来。
2. 按「这条要求不满足，基本没戏」和「这条要求有了加分没有也不影响进面试」分成两组。
3. 把候选人的经历，只对齐「必备」那一组，确认覆盖情况。

**输出结论**：「这个岗位真正的门槛是 X 和 Y，你在 X 上有直接经历，在 Y 上需要补一个说法。剩下的那 8 条你不用管，那是加分项，没有也能面。」

---

### 模型③：项目经历「能否抽象成一条产品故事线」的成熟度模型

**诊断什么**：候选人的项目经历是零散功能点的堆砌，还是可以被串成一条有逻辑的产品故事线——这决定了面试官对候选人产品思维完整性的判断。

**怎么用**：
1. 把候选人所有项目 / 功能经历列出来。
2. 问：这些项目有没有共同的用户价值主线（某个问题被完整解决了，或用户旅程的某段被完整打通了）？
3. 能找到主线：帮候选人用一句话命名这条线，把各个项目作为节点重新叙述。
4. 找不到主线：从中选 2-3 个最能证明核心能力的项目重点写，其余简略处理。

**输出结论**：有主线时，说「你这三件事可以串成一条线：找得到→开得到→不用等，这是用户体验闭环。面试官问『你做过什么』，就用这个框架来讲。」没有主线时，说「这些经历目前是散点，没有主线，建议选 X 和 Y 重点写，其他提一句就好。」

---

### 模型④：受众视角 —— 这份材料是写给谁看的

**诊断什么**：候选人（或教练）在写简历/求职信/作品式 HTML 时，有没有先锁定「真实受众是谁、他读时在找什么」。受众错判，再好的内容都是无效功；尤其容易犯的错是把「对创始人/技术合伙人岗的材料」写成「对 HR 的履历清单」，或写成「对受众喊话的推销稿」。

**怎么用**：
1. 锁定真实受众——不是「公司」，是「具体的人 + 他的动机」。JD 出现「核心成员 / 股权 / 技术合伙人 / 真实项目经验者优先」且联系人是创始人本人时，受众 = 一个懂行、且天天在受这个痛点的人，材料本质从「简历」变成「产品案例 + 能力证明」。
2. 列出这个受众会「前倾」（真跑过的系统、解决过他同款问题、能一个人闭环、经得起追问的细节）和会「反感」（被推销恭维、被教他自己的业务、堆答不上的关键词、代码行数式空泛自夸、只有总监腔没有亲手交付证明）的内容。
3. 用一条原则统一收口：**展示，不要宣称**。靠「把什么放 C 位」对齐 JD，而不是靠「声明我对齐」。

**输出结论**：例如「这份材料的受众是创始人本人，不是 HR——他要的是『你已经把我要的东西做出来过』。所以别写对齐表、别写『我能直接上手』，把你那套真跑过的 AI 电话产品摆到最前、写它怎么解决客户接入和通话闭环，让他自己得出结论。凡是对他喊话、替他总结需求、自夸匹配度的句子，删掉。」

详细写法见 `简历改写范式.md` 的「受众视角先行」章节。

### 如何追加新模型

每次辅导结束后，如果对话中产生了可复用的判断框架，按以下格式在本节末尾追加：

```
### 模型④：[模型名称]

**诊断什么**：[一句话说清楚这个模型解决什么诊断问题]

**怎么用**：[步骤，1-3 步，具体可操作]

**输出结论**：[示例结论是什么样的语气和格式]
```

追加模型不需要删改已有模型。模型库是叠加式生长，不是替换式更新。

## 三个核心焦虑的识别

每次诊断，要从候选人的原话里找出他反复提到、或明显回避的担忧，锁定恰好 3 个核心焦虑。

**为什么是 3 个**：不是 1 个，因为焦虑通常是多层的；不超过 3 个，因为每个焦虑都需要在后续的改简历和面试准备里有对应的处理动作——超过 3 个就变成了零散清单，候选人记不住、也不知道优先处理哪个。

### 识别方法

**第一步：收集候选人原话里的信号词**

听候选人描述自己的经历和担忧时，留意以下几类表达：

- 「我怕他们问到…」「如果他们追问…我可能答不上来」
- 「我不知道这段经历算不算…」「这个我其实没做很深…」
- 「感觉自己不像…（C 端 PM / 做 AI 的 / 有实际落地经验的）」
- 反复强调同一个弱点（说了两次以上的，通常是真正的核心焦虑）

**第二步：把信号归类**

这些信号通常落在三类焦虑里：

1. **经历深度焦虑**：「我做的项目不够深入 / 太边缘 / 只是执行层」
2. **身份认同焦虑**：「我不确定我算不算面试官认定的那种人（C 端 PM、AI PM、产品负责人…）」
3. **追问应对焦虑**：「面试官深挖某个细节的时候我会撑不住」

**第三步：锁定 3 个**

从候选人的具体说法里，各取一个最具代表性的表述，作为「当次辅导的 3 个核心焦虑」——这 3 个焦虑将贯穿后续所有阶段。

**示例（C 端产品候选人）**：
1. 「怕面试官深挖充电桩搜索功能的具体算法，我没有技术背景」
2. 「这段经历在 B 端平台上，怕面试官觉得我不像 C 端 PM」
3. 「项目结果数据不好看，说出来怕减分」

识别后在诊断报告里明确点出这 3 个，让候选人确认「是的，这就是我担心的」——确认即建立信任，接下来给的建议候选人才会真正去用。

## 诊断报告产出规则

诊断报告是辅导第一步的输出成果。它不是改写建议的集合，是一个「让候选人清楚自己处于什么位置、该往哪走」的结构化判断。

### 产出结构（固定顺序，不可打乱）

**第一段：本质先行**

先说清楚「这个岗位 / 这种招聘，真正在考察什么」。用 3-5 句话把招聘本质讲清楚，不是泛泛描述，要针对候选人具体的岗位类型。

作用：让候选人知道接下来的所有判断都基于什么框架，而不是「我凭感觉说的」。

**第二段：3 个核心焦虑**

把识别出的 3 个核心焦虑点名说出来。语气是陈述，不是批评，不是安慰。

格式示例：
```
你目前的 3 个核心焦虑是：
1. [焦虑①的准确表述]
2. [焦虑②的准确表述]
3. [焦虑③的准确表述]

这 3 个焦虑是真实的，不是多想——接下来我们针对这 3 个来处理。
```

**第三段：判断模型结论**

用一个或两个判断模型，输出整体判断。这是诊断报告的核心，不是罗列问题，是给出有逻辑的判断。

格式：说清楚用了哪个模型的逻辑（不需要点模型名字，直接用结论语言），给出判断，说清楚接下来的优先顺序。

示例：
```
从这次诊断来看：

你的核心匹配点在 X，这是你最强的信号，要重点打。
你在 Y 上的经历是散点，目前没有主线——这是最需要解决的一个问题。
Z 这条要求是加分项，你现在的时间不要花在这里。

接下来：先处理 Y，再打磨 X 的表达，Z 不碰。
```

### 做减法规则

- 诊断报告总字数控制在 400 字以内（如有必要可略超，但不超过 600 字）
- 不在诊断报告里给改法细节——诊断是诊断，改法是下一步
- 不平级列出 10 条「你的问题」，只说 3 个焦虑 + 模型结论，其余降级
- 不鸡汤，不夸「你的经历很丰富」，不说「只要努力一定能过」
