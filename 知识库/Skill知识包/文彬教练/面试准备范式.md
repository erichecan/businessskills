# 面试准备范式

> 本文档是 `eric-coach` skill 的面试准备执行手册。skill 运行「面试准备阶段」时读取此文件，与「教练人设与方法论.md」配合使用，产出可直接给候选人的面试准备包。

---

## 深挖点预测

**用途**：从改后简历的每个项目反推面试官会追问什么，提前把候选人可能卡死的问题列出来，逐一准备答法。

**从简历反推问题的四类追问逻辑**：

面试官不是随机问问题，他们的深挖方向是固定的，来自对简历的四类质疑：

1. **数据怎么来的**：简历里写了数字（转化率 +12%、DAU +2万），面试官会问「这个数字你怎么测的」「数据口径是什么」「上线前后的对照组怎么设计的」。候选人如果回答不出测量方法，数字就变成负分。
2. **你的判断依据是什么**：写了「优先级排序」「选择了方案 A 而不是方案 B」，面试官会追问「为什么做这个判断」「当时有哪些选项」「你是基于什么信息做决策的」。考察的是判断力，不是结果。
3. **能力下线了怎么办**：写了依赖某个数据源、某个合作方、某个平台的功能，面试官会问「如果这个条件不存在了，你怎么办」「有没有备案」——这是在考察产品判断在不利条件下是否还成立。
4. **为什么这么设计**：写了一个产品方案（界面设计、流程改造、功能架构），面试官会问「有没有考虑过其他方案」「这个方案的核心假设是什么」「用户为什么会用这个」。

**操作步骤**：

1. 拿出改后简历，逐段过一遍。
2. 每一段项目经历，按四类追问逻辑各生成 1-2 个具体问题。
3. 把问题列成清单，下一步针对每个问题给答法。

**示例（充电场景「找得到→开得到→不用等」）**：

| 简历项 | 四类追问 | 具体面试问题 |
|--------|---------|------------|
| 进站放弃率下降 40% | 数据怎么来的 | 「这 40% 怎么测的，你们有 A/B 测试吗？」 |
| 主导选择精准引导地址方案 | 判断依据 | 「当时有没有考虑别的方案，为什么选这个？」 |
| 协调地图 SDK 团队完成接入 | 能力下线 | 「如果地图 SDK 不配合改，你有备选方案吗？」 |
| 设计精准引导地址字段 | 为什么这么设计 | 「为什么是加字段而不是让用户自己上报实际入口坐标？」 |

**示例（AI 电话场景）**：

| 简历项 | 四类追问 | 具体面试问题 |
|--------|---------|------------|
| 端到端延迟从 3.2 秒降至 1.1 秒 | 数据怎么来的 | 「这个端到端是怎么定义的，从哪到哪，怎么测的？」 |
| 识别 TTS 合成为最大瓶颈 | 判断依据 | 「你怎么定位到 TTS 是瓶颈的，用了什么方法？」 |
| 推动切换流式 TTS 方案 | 能力下线 | 「如果流式 TTS 引入了新的断句问题，你怎么处理？」 |
| 设计端到端延迟监控看板 | 为什么这么设计 | 「这个看板具体监控哪些指标，告警阈值怎么定的？」 |

**目标**：辅导结束时，候选人手里有一份清单，知道每个项目最可能被深挖的 3-4 个问题是什么。这份清单是下一步「标准答法结构」的输入。

## 标准答法结构

**用途**：针对深挖点预测清单里的每个问题，给出「怎么答 + 为什么这么答」。答法不是背台词，是一套可以在现场灵活运用的思路结构。

**核心原则**：答法必须回扣体验闭环与产品判断，而不是堆细节。细节是支撑，判断才是面试官真正想看的东西。

**可套用的答题结构（「判断-证据-闭环」三步）**：

```
第一步：给判断
「当时我的判断是…（结论先行，一句话说清楚你做了什么选择/决定）」

第二步：给证据
「依据是…（用户数据 / 竞品分析 / 用户访谈 / 技术约束 / 业务目标，选最直接的一条）」

第三步：回扣闭环
「这个决定在整体上解决了…（指向体验闭环或产品故事线的哪一环，让面试官看到你在想的不是这一个功能，而是整条链路）」
```

**四类追问的专项答法**：

### 「数据怎么来的」类问题

答法：先说测量方法，再说口径定义，再说局限性（主动说出局限性比被追问出来好）。

```
「这个 40% 是我们用 A/B 测试测的。实验组是上线了精准引导地址的城市，对照组是还没上线的城市，
对比的是用户打开导航到开始充电的完成率。局限性是两组城市的充电桩密度不完全一样，
所以我们在报告里也注明了这一点，实际改善幅度可能略有高估。」
```

为什么这么答：主动说出局限性显示头脑清醒，比被面试官追问出来再承认要强得多。

### 「判断依据」类问题

答法：先说信息来源，再说判断逻辑，再说当时的其他选项和为什么没选。

```
「我当时主要基于三个信息：用户投诉里有 15% 是说找不到充电站入口；
竞品在引导地址上的处理比我们粗糙，这说明是个普遍痛点；
技术侧评估加字段的改造成本只需要两周。
也考虑过让用户自己上报实际入口坐标，但用户生成内容的质量难以控制，
引入了新的维护成本，所以最后选了我们自己采集的方案。」
```

为什么这么答：说出「也考虑过其他选项」是面试加分项，证明你做的是判断，而不是拍脑袋。

### 「能力下线了怎么办」类问题

答法：先承认约束确实存在，再说当时的风险意识，再给备案思路（哪怕当时没真的做，能说出思路也算）。

```
「这个风险当时确实考虑过。如果地图 SDK 不配合改，我们的备案是在充电站详情页用文字描述
入口位置（比如'从南门进入，第 3 排'），先解决信息有没有的问题，再慢慢推 SDK 的改造。
事后来看这个风险没有触发，但产品设计里我们留了这个降级方案。」
```

为什么这么答：「能力下线」类追问考察的是产品判断的鲁棒性，不是让你证明所有前提都成立。有备案思路比说「这种情况没发生过」要强。

### 「为什么这么设计」类问题

答法：先说核心假设，再说用户旅程中的位置，再说设计取舍。

```
「核心假设是用户在导航起点输入的时候，对'充电站'的识别能力比对'精确入口坐标'更强。
所以我们的设计是在起点展示标准地址，到站后再给精准引导——两步走，
而不是一开始就给一个用户可能看不懂的精确坐标。
取舍是我们在'到站前'和'到站后'的体验之间选择了分开处理，成本是需要两次信息展示。」
```

为什么这么答：回扣用户旅程（「到站前」「到站后」这两个节点）证明你在想体验闭环，而不是在解释一个孤立的功能。

**一个不该犯的错误**：

面试官问「为什么这么设计」，候选人答「因为用户需要」——这是最弱的答法。面试官知道用户需要，他想知道的是你基于什么信息做了这个判断、你的设计取舍是什么。答法里必须有「信息来源」和「取舍」，缺一就是没回答到点上。

## 心理建设

**用途**：处理候选人在面试准备阶段的三类真实心理障碍。不是鸡汤，是可操作的认知重构和具体应对动作。

**三类常见心理障碍**：

### 障碍①：怕被深挖细节，感觉细节不够

**候选人原话信号**：「如果面试官一直追问，我可能撑不住」「这个项目我只负责了一部分，深挖到其他部分我就答不上来」

**认知重构**：

面试官并非每题都深挖，也不是什么都懂。

面试官在一场面试里要评估一个人的全貌，能用来深挖某个技术细节的时间是有限的。实际情况是：他们会在几个关键点上深挖两三个来回，其余的点点到为止。候选人怕的「无止境深挖」在现实里极少发生。

而且面试官对候选人项目领域的了解，往往不如候选人深——他们知道大方向，不一定知道「充电桩进站坐标这个具体问题」的技术细节。候选人把自己做过的事说清楚、说有逻辑，面试官大概率点头，不会追着你问坐标 SDK 的接口是什么。

**具体应对动作**：

如果面试官真的深挖到候选人不清楚的部分，用这个句式：

「这个部分在我们团队里是 [同事/技术负责人] 负责的，我在这里的角色是 [需求定义/方案评审/数据验收]。我们的协作方式是……」

不要绕，不要模糊，直接画清楚边界，然后展示协作视角——这比撑着给一个半懂不懂的答案强得多。

### 障碍②：不自信，感觉自己不像目标岗位的人

**候选人原话信号**：「我不确定我算不算 C 端 PM」「感觉我做的跟他们要的不完全对」「跟其他候选人比我可能不够格」

**认知重构**：

候选人价值在「头脑清醒、对行业/自我认知清楚」，大于项目深度本身。

大多数候选人进面试间，展示的是经历。能让面试官觉得「这个人不一样」的，是在讲经历的时候展示出清醒的判断——知道自己做了什么、为什么做、做成了什么程度、下一步该怎么做。这比「我做了十个项目」更有说服力。

「感觉自己不像」这个焦虑，很多时候是候选人在用一个模糊的、想象中的完美候选人标准来衡量自己。面试官的真实期待比候选人想象中现实得多：有真实经历 + 能讲清楚 + 头脑在转，就已经超过大多数候选人了。

**具体应对动作**：

写下你做过的最具体的一件事——不是「负责过产品」，是「设计了这个具体流程，解决了这个具体问题，结果是这个」。在面试前把这件事练习讲三遍，每次讲完问自己「面试官听完能不能判断我做过什么」。能判断，就有了底气的来源。

### 障碍③：怕被问到对不上 JD 的部分

**候选人原话信号**：「JD 上有些要求我没做过，怕被问到」「他们想要 X，但我做的其实是 Y」

**认知重构**：

JD 上的要求不是每一条都会被考，也不是每一条都是真门槛。

招聘方写 JD 时习惯性把所有「理想候选人」的标签都列上，实际评估时只盯住 2-3 个核心能力点。哪些是真门槛，在改简历阶段的「JD 对齐」里已经拆解过了。没覆盖到的那些，大概率不会被当作淘汰依据。

**具体应对动作**：

如果面试官真的问到候选人没有的经历：「我在这个方向上没有直接经历，我做过 [最接近的经历]，当时的处理思路是……我理解这个岗位在 [X 方向] 的要求，我的计划是……」

承认没做过，然后展示学习能力和思路——比绕过去或强撑一个假经历要好。

**心理建设的执行时机**：

心理建设不是在正式面试前临时抱佛脚。在面试准备包完成之后，和候选人逐一过每个焦虑点，针对他的具体情况给到对应的认知重构和句式。候选人在准备阶段把这些话说出声，练习几遍，比在面试间里第一次启动要稳得多。

## 面试准备包硬约束

输出面试准备包之前，对照以下约束全部过一遍，有一条不满足就不能给候选人。

**必须针对客户的具体焦虑**：

- ⛔ 不允许给通用面试技巧（「多用 STAR 法则」「注意眼神交流」）——这不是文彬教练辅导的内容
- ✅ 每一条准备建议，必须可以对应到候选人在本次辅导中说出来的一个具体焦虑或一段具体经历
- ✅ 面试准备包开头必须点名「本次辅导的 3 个核心焦虑」，后续所有内容围绕这 3 个展开

**必须包含「面试官会问什么 + 你怎么答 + 为什么这么答」三件套**：

每一个预测问题，必须同时给出：

1. **面试官会问什么**：具体问句，而不是「面试官会问项目深度」——要写「『这个转化率提升 12% 你们怎么测的？』」
2. **你怎么答**：用「判断-证据-闭环」三步结构给出可以直接练习的答法模板，允许候选人用自己的内容填入
3. **为什么这么答**：说清楚这个答法背后的逻辑，让候选人理解，而不是死记答案——没有逻辑的答案现场会变形

**必须含心理建设段**：

- ✅ 针对候选人本次辅导中表现出的具体心理障碍，给出对应的认知重构（参照「心理建设」章节的三类模板）
- ✅ 心理建设段必须给出可操作的具体句式或练习动作，不允许只有「你没问题的」这类泛泛表述
- ⛔ 不说「面试会有挑战，但相信你可以克服」——这是鸡汤，不是辅导

**格式要求**：

- Markdown 格式，可直接发给候选人
- 结构固定：①3 个核心焦虑确认 → ②深挖点清单（问题列表）→ ③每个问题的三件套 → ④心理建设段
- 总字数控制在候选人能在 30 分钟内读完并练习的范围内，不要写成一本书

**输出前最后一问**：

看着面试准备包，问自己：「候选人拿着这份材料，能不能知道明天面试要讲什么、怎么讲、当被追问时怎么稳住？」

如果能，输出。如果不能，继续补。
