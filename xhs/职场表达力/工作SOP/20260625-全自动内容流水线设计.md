# 全自动内容流水线设计（含视频生成）

> 2026-06-25 · 目标：把"采集 → 改写 → 审核 → 重写到过线 → 出视频"串成一条自动流水线，**只把过线的内容推到你面前，失败的自动重写、不打扰你**。
> 本文＝T3/T4 自动审核-重写环的可落地设计 + 视频生成流程的实地勘查 + 一个必须你拍板的路线分叉。

---

## 一、整条流水线（5 个任务）

```
T1 采集        T2 改写              T3 审核            T4 重写到过线        T5 出视频
─────────    ──────────────    ──────────────    ─────────────────   ────────────
digest        repurpose         eric-xhs-audit     audit≥85 才放行       文案→成片
(已有)         (已有,产大纲)      (已有skill,缺自动)  (全新,自动循环)       (半成品,缺闭环)
关键词池/      选题大纲docx        100分7维+红线       不过线→按意见重写     录屏画外音 / AI合成
记忆库/        选题库.csv         →通过/打回         →再审→…(≤N轮)       (路线未定,见第四节)
高热结构库                                         只输出过线成稿
```

**核心理念**：T3+T4 合成一个**自评-自改闭环**，你设定的"爆款门槛"（如 audit ≥85）就是出口。低于门槛的稿子在后台自动迭代，你永远只看到通过的。

---

## 二、T3 审核任务（自动化 eric-xhs-audit）

现状：`eric-xhs-audit` skill 已建好（100 分 7 维加权 + 5 红线 + 晋级线预测 + 一句改法），但要靠人手动调用。

改成自动：
- **输入**：T2 产出的成稿（注意——当前 T2 只产"选题大纲"，不产成稿。要让审核有东西可审，T2 必须升级为"产成稿"，或新增一个 T2.5 成稿任务。见第三节）。
- **动作**：对每篇成稿按评分卡打分，输出结构化 JSON（总分 / 各维分 / 命中红线 / 最高优先级改法）。
- **留痕**：写 `审核记录.csv`（日期 | 选题 | 轮次 | 总分 | 是否过线 | 主要扣分项 | 改法）。
- **出口**：≥85 → 进 T5；<85 或踩红线 → 交给 T4。

## 三、T4 重写到过线（全新，自动循环）—— 这是你说"还没做"的第四个

这是把"审核"变"自愈"的关键。设计成一个**有限次自改循环**：

```
draft = T2成稿
for 轮次 in 1..N(建议N=3):
    报告 = audit(draft)
    if 报告.总分 >= 85 and 无红线:
        标记[通过], break
    draft = 按报告.最高优先级改法 + 各维缺失项 重写(draft)   ← 调 eric-content + 知识框架.md
若 N 轮仍不过:
    标记[需人工], 进"待你看"队列(附最后一版+审核报告), 不自动发
```

要点：
- **重写不是从头生成**，是"针对审核扣分项定点改"（喂入：原稿 + 审核报告 + 知识框架.md 的方法论/红线 + 高热结构库.md 的本账号套路）。
- **防止无限循环**：硬上限 N 轮；若分数连续两轮不升反降，回退到最高分版本并转人工。
- **只输出过线的**：通过的进 T5 队列；不过线的进"需人工"小队列（你想看才看），绝不自动发布。
- **留痕**：每轮存一版，方便你回看"它是怎么从 67 改到 88 的"，也是反哺评分卡的语料。

> 这一环把你最在意的诉求落地了：**失败的你不用看，系统自己改到好为止，改不动的才轻轻举手。**

## 四、T5 视频生成 —— 实地勘查结果 + 一个必须拍板的分叉

仓库里有一套半成型视频工具 `xhs/职场表达力/工具/20260608-zhichang-demo/`，我摸清了它的真实机制：

**技术栈**：用的是 HeyGen **HyperFrames**（`npx hyperframes` CLI），原理是"**写网页＝写视频**"——用 HTML+GSAP 把每个分镜动画写出来，无头 Chrome 逐帧截屏编码成 MP4。`index.html` 是一条 116.5s、10 场景（Hook→CTA）的墨黑金字成片，**已写好但从未渲染落盘**。

**配音**：5 个 TTS 脚本，最终方案是 **Fish Audio 克隆声音 + ffmpeg 磁性后处理**（低频+4dB/临场/去齿音/压缩/微混响，调成"磁性嗓"），语速 ×1.2。

**端到端步骤**：写 10 段口播文案 → `gen-tts-myvoice.py` 出 vo1~vo10.wav + 每段时长 → **人工把时长回填进 index.html 的时间轴**（最大手工卡点）→ 调画面 → `npm run render` 出片。

**已自动 / 仍手动**：TTS、磁性处理、逐帧渲染、字幕词级对齐都已自动；**文案→分镜编排、音画时长回填**仍纯手工——这是"全自动出片"差的最后一公里。

**缺什么才能全自动从文案出片**：①文案→分镜结构化转换器 ②TTS 时长自动回填时间轴（唯一硬手工环）③场景模板库（S1-S10 抽象成传参即生成）④一键串联脚本。

### ✅ 路线已定：混合 —— 真人声 + AI 动画插片
（2026-06-25 拍板）配音用**你本人真声**（守住信任与合规、不踩 AI 配音红线），画面里**只有"不说话的部分"用 HyperFrames AI 合成插片**：片头 EP 角标/标题钩子、金句卡、数据动画、白闪转场、结尾 CTA。说话段走真人录屏。

这条路线的好处：既拿到 demo 的动画生产力（片头/金句/数据这些最费手工的部分自动出），又不违 SOP（人声真、无 AI 语音、无 AI 文生图）。

**要建的三块（音画对齐比全 AI 版更轻，因为插片是短固定片段、卡在标记点）：**
1. **文案→混合分镜脚本生成器**：把过线成稿自动切成「真人口播段（5 段式）＋ AI 插片点」两轨——口播段给你照着念，插片点标好类型（片头/金句/数据/转场/CTA）和文案。
2. **HyperFrames 插片模板库**：把片头、金句卡、数据动画、白闪转场、CTA 抽象成 5 类可传参模板（传一句文案即生成一段几秒的金黑风插片），复用 index.html 已有的视觉锤。
3. **真人音轨 + 插片合成**：你录完口播音轨/录屏后，按脚本标记点把 AI 插片叠加/切入；插片时长固定，对齐只需锚到标记时间点，省掉全 AI 版"逐段时长人工回填"的最大卡点。

**顺带清理**：Fish Audio 的 API Key/Voice ID 仅在你将来想做"试听小样"时才用，挪进环境变量；`compositions/` 下英文模板残留删掉。

### 另外两个隐患（顺带记录）
- Fish Audio 的 **API Key、Voice ID 明文硬编码**在脚本里，建议挪进环境变量。
- `compositions/` 下 5 个文件是 HyperFrames 官方英文模板残留，与本项目无关，建议清掉避免误导。

## 五、落地顺序建议
1. **先把 T2 升级到"出成稿"**（否则 T3 审核无米下锅）——可复用 app 工坊的 draft 能力，或扩写任务。
2. **建 T3+T4 自评-自改环**（纯文本，不依赖视频，风险最低、收益最大，**先做**）。
3. **T5 混合视频**：先建"文案→混合分镜脚本生成器"（纯文本、立刻可用，让你录制有据可依），再做插片模板库与合成（需要在 zhichang-demo 里写 HyperFrames 模板，工程量较大，后做）。
