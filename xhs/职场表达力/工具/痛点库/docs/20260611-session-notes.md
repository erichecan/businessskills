## 本次完成的事

### 1. 第一条视频脚本（两轮迭代）

**选题**：面试表达 — 结论先行机制  
**对应案例**：南大 CS 应届，面了 20 多家全卡中后期，改一句话两周拿字节 offer

**v1 核心问题**（eric-content 五维诊断发现）：
- 认知落差不够 ❌：「结论先行」受众已知，前 10 秒没有反常识触发
- 悬念在 5 秒内消解：「问题出在哪？」→「是顺序问题」，观众当时反应是「我知道」然后划走
- 可信度空白：「我有个学员」，没有建立为什么听你讲

**v2 改动逻辑**：
- Hook 从「描述痛」改为「打脸已知方案」：「结论先行，你改了，面试官还是打断你」
- 反常识从「顺序问题」改为「不是位置，是内容」：你以为给的是结论，其实是背景
- 机制提前到第二段，一句话切开：背景句 vs 答案句
- 话题范围扩展：不只针对求职者，覆盖所有「改了还是没用」的人

**最终脚本**：见 `20260610-script-video01.md`

2. 反常识结论（5–10s）
3. 机制拆解（10–30s）

## 下一步要做的事

### 优先级 1：爆款审核员 Skill（新需求）

**目标**：一个能持续自主学习、提炼爆款公式、回来审核内容的 skill

**核心能力设计**：

```
爆款审核员 = 学习模式 + 审核模式

学习模式（输入爆款视频/文案）：
  → 提取：Hook 类型 / 机制讲法 / 案例结构 / CTA 句式
  → 存入：知识库/爆款公式库/

审核模式（输入待发内容）：
  → 对照公式库打分
  → 输出：哪段弱、为什么弱、参考哪条爆款改
```

**与现有 skill 的关系**：
- `eric-content`：5维诊断，偏原则性，不自主学习
- `eric-hook`：只管开头
- 新 skill（暂定 `eric-viral-audit`）：基于真实爆款数据，持续迭代，能给出「对标案例」级别的改法建议

**需要解决的问题**：
1. 爆款样本库从哪来？（竞品拆解 → `eric-xhs-deconstruct` / `eric-benchmark`）
2. 公式提炼存到哪？（建议新建 `知识库/爆款公式库/` 目录）
3. 审核输出要多具体？（建议：打分 + 对标案例 + 最高优先级改一句话）
