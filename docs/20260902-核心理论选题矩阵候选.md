## 2×2 矩阵说明

- **横轴——主张类型**：知识型主张（陈述性方法论）/ 判断型主张（程序性甄别能力）

- 四格命名：①法则实证（知识×展示）②方法溯源（知识×经历）③眼光验证（判断×展示）④决断复盘（判断×经历）

## 理论②：情绪顺序理论（先接情绪/事实→再给信息/边界→最后方案，顺序颠倒全盘作废）

对应力：边界力、反馈力

### 场景：给下属/同事负面反馈

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 我从不上来就说"你这方案不行"，先接后给的三步法，我带的组离职率比隔壁组低一半 |
| ②方法溯源 | 以前批评人直接列问题清单，对方当场就炸；后来才摸索出先说一句"我知道你已经很赶了" |
| ③眼光验证 | 一听对方开口的语气，就知道这场反馈能不能推进 |
| ④决断复盘 | 判断某个下属情绪到了临界点，先花 2 分钟只听不谈工作，后来那次是我带团队以来效果最好的绩效面谈 |

### 场景：拒绝加班/临时任务

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 我从不说"不行"，先接对方的"确实很急"再划边界，同事都说我"很难被讨厌地拒绝" |
| ②方法溯源 | 以前一被临时加任务就炸毛，关系搞僵；后来想明白要先认对方的"急" |
| ③眼光验证 | 看一眼对方发消息的措辞，就知道这个"急"是真急还是甩锅式的急 |
| ④决断复盘 | 领导临时甩"今晚必须"的任务，我先说"知道这个客户很重要"再说明早交，对方自己都不好意思催了 |

### 场景：安抚情绪激动的人再谈规则

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 客户在电话里骂人，我从不先讲流程，永远先接情绪——我们组投诉复发率全公司最低 |
| ②方法溯源 | 刚入行被客户骂懵了直接讲政策，对方更生气；带教教我先接情绪再推流程 |
| ③眼光验证 | 一听音量和用词，就能判断这通电话能不能 5 分钟内平息 |
| ④决断复盘 | 客户已经在骂脏话，我判断他要的是被听见不是解决方案，沉默 10 秒让他说完，最后他反而写了表扬信 |

## 理论③：战场转移理论（口头对抗无意义，把争议从嘴上移到留痕规则层）

对应力：化解力

### 场景：被同事当众甩锅

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 甩锅从来不靠对骂赢，我永远把口头指责变成一封确认邮件，这招用了很多年从没被坐实过 |
| ②方法溯源 | 第一次被甩锅在会上急了跟对方吵，全场只记得我"情绪失控"；后来才明白该闭嘴发邮件 |
| ③眼光验证 | 对方开口甩锅那一秒，我就能判断他是要当众看我下不来台，还是真觉得是我的错 |
| ④决断复盘 | 那次他当众说"数据是你给错的"，我没反驳，散会后发了带原始截图抄送领导的邮件，他后来私下说"算了" |

### 场景：被造谣中伤

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 面对造谣我从不当面对质，只做一件事——把事实清晰留痕给关键人看 |
| ②方法溯源 | 第一次被传闲话当面对质，对方添油加醋传得更凶；后来学会直接告诉利益相关人事实 |
| ③眼光验证 | 一听谣言的传播路径，就知道该不该出面回应——回应等于加热度 |
| ④决断复盘 | 判断直接对质造谣者只会两败俱伤，转而私下跟领导说清事实，谣言两周后自己消失 |

### 场景：被孤立第二天怎么办

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 被孤立第二天我从不挨个解释，只做该做的工作留下书面记录，半年后孤立我的人先绷不住 |
| ②方法溯源 | 一开始拼命想融入，越讨好越被看不起；后来想通工作留痕比讨好有用 |
| ③眼光验证 | 看孤立是几个人一起还是一人带头，就知道该硬扛还是该找组织出面 |
| ④决断复盘 | 判断带头那人只是想看我崩溃走人，什么都没说，把项目做出结果抄送所有人，孤立不到一月自己散了 |

## 理论④：pratfall 示弱候选（示弱要看有没有先立住能力认可，未经验证）

对应力：示弱力

### 场景：面试被问缺点

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 我从不背话术模板，先讲一个做成的具体结果，再讲真实短板，效果比背模板的人稳 |
| ②方法溯源 | 刚开始照模板说"我的缺点是过于追求完美"，面试官当场就笑；后来才明白得先证明能力 |
| ③眼光验证 | 听候选人讲缺点的顺序，就能判断他懂不懂这个逻辑——先摆实力的人通过率明显更高 |
| ④决断复盘 | 有次候选人先讲具体项目结果，再说"这件事上判断慢了三天"，那一刻反而觉得可信，后来录用了他 |

### 场景：述职坦白失败案例

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 述职里我从不回避那次失败项目，但永远先摆战绩再讲失败，评委记住的是"敢讲真话又有实力" |
| ②方法溯源 | 第一次述职把失败案例排最前想显得谦虚，评委当场追问"那你凭什么晋升" |
| ③眼光验证 | 一看述职稿结构就知道这场答辩过不过——先讲失败开场的十有八九被追问到下不来台 |
| ④决断复盘 | 有下属坚持先讲战绩再坦白一次失败决策，评委反而追着问细节，后来说这是最有说服力的一场述职 |

### 场景：团队里带头认错道歉

| 格子 | 候选选题 |
|---|---|
| ①法则实证 | 我认错从不空口说抱歉，先摆一句"这个月我们组交付的那三件事"再认错，团队反而更服 |
| ②方法溯源 | 以前一犯错就先道歉，团队觉得我没底气；后来才明白得先亮结果再认错 |
| ③眼光验证 | 看团队犯错后第一反应是甩锅还是自己先扛，就知道这个团队的信任度 |
| ④决断复盘 | 判断这次事故必须我先扛，先说清楚三个月前那次上线是我们扛下来的，再认这次的错，团队士气反而没垮 |

## 使用方式

1. 挑一条觉得有戏的候选，过 `/eric-xhs-topic` 4 维评判（受众精准度/认知落差/商业价值/执行可行性）
2. 过了之后用 `/eric-xhs-rhetoric` 做传播设计蓝图（这批候选的新闻性/争议层级都还没扫描过）
3. 再进 `/eric-xhs-title` 起标题、`/eric-hook` 优化开头

理论②③④的 confidence 都在 medium/low，评判时认知落差那一档打分要保守——这些理论本身还没被账号自己的数据验证过。
