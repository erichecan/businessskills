# 采集频率限制

适用：职场探词、每日采集、旧版 CDP/opencli 探词，以及喜马拉雅 AI / 纳瓦尔 / 财富自由三条小红书素材采集线。喜马拉雅发布不受影响。

## 默认参数

| 参数 | 秒 | 行为 |
| --- | ---: | --- |
| request_gap_seconds | 15 | 上一次访问完成后，下一次访问至少等待 |
| keyword_gap_seconds | 45 | 上一次搜索完成后，下一次搜索至少等待 |
| search_dwell_seconds | 20 | 搜索结果页停留；API 搜索结果也等待后再继续 |
| note_dwell_seconds | 30 | 正文页停留；API 正文结果也等待后再继续 |
| close_delay_seconds | 8 | 网页提取结果后、关闭或返回前等待 |
| scroll_step_seconds | 5 | opencli 搜索结果懒加载的逐次滚动间隔 |

这些数值是本次选定的保守限制，未通过平台标定，不保证消除风控。

默认每次等待独立随机取值：基准到基准的 1.5 倍。对应请求间隔 15–22.5 秒、搜索停留 20–30 秒、正文停留 30–45 秒、提取后/关闭等待 8–12 秒、搜索间隔 45–67.5 秒、滚动间隔 5–7.5 秒。滚动循环内每一步也重新抽样。

`jitter_ratio` 默认 0.5；可设 0–3，0 表示关闭随机浮动，其他值表示额外等待比例，最低等待始终保留。

## 共用配置与访问队列

生效配置：`~/.config/xhs-collection/pacing.json`；仓库默认配置：`config/collection-pacing.json`。
直接修改生效配置后，后续访问重新读取，不需要重启定时任务。时间参数必须是大于等于 1 的有限数；随机比例需在 0–3 之间。

三个项目共用 `queue.lock` 中的完成时间与搜索时间。锁覆盖请求及等待过程，避免不同进程同时采集。异步等待锁不会阻塞事件循环，进程结束后系统释放锁。`XHS_PACING_DIR` 可指定隔离目录，测试使用临时目录。

小红书签名在排队结束后生成，避免长时间排队导致签名先过期。MediaCrawler 请求重试为 20–40 秒随机等待；喜马拉雅外层重试基准由 3/12/30 秒改为 30/60/120 秒，每次额外随机增加 0–50%，仍需遵守共用队列。

## 实现及部署

运行 `python3 scripts/deploy_collection_pacing.py` 安装缺少的补丁、共用模块与默认配置；重复运行会验证已部署内容，不覆盖已有配置。`--check` 仅验证。定时任务直接执行这两个仓库中的脚本，下次运行读取更新，不需要重启 Chromium 或中断正在运行的任务。

- `scripts/collection_pacing.py` 是共用队列。喜马拉雅 `src/collection_pacing.py` 与本机 MediaCrawler `tools/collection_pacing.py` 使用软链接复用它。
- `scripts/collection_pacing.mjs` 通过采集子进程的 `NODE_OPTIONS --import` 装载，给 opencli Page 增加停留、提取后等待、关闭等待和滚动限速。没有修改 npm 包；其他命令不装载该钩子。
- MediaCrawler 的本机变更见 `scripts/xhs-probe/patches/20261005-collection-pacing.patch`，升级外部工具后先检查补丁再恢复。与前一个登录保留补丁配套使用。外部文件已有 `.before-pacing-20261005` 备份。
- MediaCrawler 自动采集超时为 60 分钟，opencli 单次命令为 180 秒（排队时间不计入）；较长停留和跨项目排队会增加总耗时。
- 采集成功时只关闭本轮自建工作标签页，关闭前等待 8–12 秒。登录/安全验证失败页面保留，借用的浏览器上下文和用户原有页面不关闭。
- API 后端限制请求节奏，没有额外构造鼠标、输入或剪贴板动作。

`node scripts/test_collection_pacing.mjs` 用模拟 Page 验证搜索/正文停留、提取后等待、关闭等待、滚动限速与其他站点不受影响。测试缩短等待并隔离状态，不向平台发送请求。
