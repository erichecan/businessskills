# 20260815 闸门与去重修复

> 起因：Eric「每天都写不出稿，面对那么多火爆关键词只能写出一个角度」。
> 诊断后推翻了原假设 —— **不是写不出，是写出来发不出去**。

## 诊断结论（数据，2026-08-15 实测）

| 事实 | 数字 |
|---|---|
| 词库已验证未写的词 | 83 个 |
| 发布日志已发 | 23 篇 |
| **曾达标（≥80 且无红线）但未发布** | **55 篇** |
| 其中「最新处置=发布」仍未发 | 19 篇 |
| 8 月以来审核处置 | 返工 134 · 发布 72 · 待人工 31 · 归档 14 |

**19 篇的真实拦点（逐篇跑 draft_check --file 实测）：**

```
 17  机械项「CTA 没给编号选项」
  5  同词已发 3 篇（MAX_PER_KEYWORD）
  1  无成品图
```

### 根因：规则变更没有做存量迁移

CTA 判据在 **2026-08-08 换口径**（draft_check.py:30-33 注释原文：
「原来只查『有没有 CTA』——18 篇稿全都通过」），从「有没有 CTA」
改成「有没有 2 个以上字母/数字编号选项」。

被卡的 17 篇写于 08-02~08-08，**写的时候是合格的、独立审核判「发布」的**。
规则一改，它们集体变成不合格，而且没有任何环节回头处理它们 ——
既不在返工队列（rework_queue 只取处置=返工，它们是「发布」），
也过不了闸门。这就是 55 篇积压的主要来源。

**这是一类机制缺陷，不是一次失误**：机械项每次收紧都会静默废掉一批存量稿。

### 次要缺陷（各自独立、都已验证）

- **D1** `auto_publish.gate()` 只看 `trusted[-1]`（最新一条审核记录）。
  曾判「发布」的稿被后续改坏的低分记录否掉，永久出不去。**实测命中 3 篇**：
  `08-08_绩效被打低分`(最佳87→最新83) / `08-07_汇报被打断`(最佳86→最新83，审了12次)
  / `08-03_晋升答辩有可能不过`(最佳86→最新79)。
- **D2** `refine_loop.KEEP_PASSED` 仍要求模型守住「引语密度≥0.8/百字 ·
  具体名词≥2.0/百字」，**这两条 08-11 已从 draft_check 删除**（draft_check.py:236-249）。
  prompt 在为已废除的规则消耗模型注意力，且诱导堆砌。
- **D3** `refine_loop.py:1024` 硬编码 `差 {85-item['score']} 分到线`，
  而 PASS_SCORE 已是 80 —— 81 分的稿会被打印成「差 4 分」，实际已过线。
- **D4** `independent_audit.py` 喂给模型的 prompt（:469-471）与 docstring（:81-90）
  仍写「≥85 发布 / 75-84 返工」，代码是 `PASS_SCORE = 80`。
  模型打分锚点被钉在 85，这正是「总卡在 80-84」的成因。
