# 小红书数据预测 · 调研与模型 v1

> 2026-08-03。用途：给每篇成稿预测 7 天数据（观看/赞/藏/评/转 + CES），
> 发布满 7 天后用真实数据复盘偏差，迭代模型。
> ⚠️ **v1 是先验模型，不是拟合模型**——本项目只有 2 篇已发布笔记且都是发布当天数据，
> 样本量根本不够拟合。所有系数都标了来源，等真实数据回填后按 T5 复盘校准。

## 一、调研结论（公开方法论）

### CES 评分与流量池

```
CES = 点赞×1 + 收藏×1 + 评论×4 + 转发×4 + 关注×8
```

阶梯式流量池：笔记发布 → 初始曝光 **0–200** → 24–48h 内按 CES 打分 →
达标进入二级池 **200–500** → 逐级放大。低分则减少推荐。

### 门槛与基准

| 指标 | 数值 | 来源 |
|---|---|---|
| 全域平均互动率 | 3% | 公开运营资料 |
| 图文种子推荐点击率门槛 | ≥2.5% | 同上（视频 ≥4%） |
| 第二阶互动率门槛 | ≥5% | 同上（停留 ≥25 秒） |
| 搜索流量占全站比 | 50%–65% | 多来源，口径不一 |
| 搜索转化率 vs 推荐流 | 4.1 倍 | 花叔《小红书创作最佳实践》 |

### 搜索排名四维权重

内容质量 40% · 用户互动 30% · 账号权重 20% · 实时热度 10%

→ 对我们的含义：**账号权重只占 20%**，新号靠内容质量和关键词布局能排上去；
这正是搜索流策略成立的前提。

### 两条流的数据形态不同

- **搜索流**：慢热、长尾。曝光在 7 天内持续爬坡，用户带着问题来，
  **收藏意愿显著高于推荐流**（收藏是"我要用"，不是"我喜欢"）。
- **推荐流**：初期爆发依赖点击率（封面+标题），过不了 2.5% 点击率门槛就沉；
  过了则 24–48h 内快速放大。刷到就赞，收藏率相对低。

→ 两条流必须用不同的预测口径，不能共用一套系数。

| 笔记 | 发布天数 | 观看 | 赞 | 藏 | 评 | 转 | 互动率 | CES |
|---|---|---|---|---|---|---|---|---|
| 晋升答辩被评委问倒怎么办 | 0 | 262 | 9 | 5 | 0 | 1 | 5.7% | 18 |
| 第三轮hr面试一般会问什么 | 0 | 129 | 3 | 0 | 0 | 1 | 3.1% | 7 |

**只能读出三件事，其余都是噪音：**
1. 初始曝光 129–262，与"初始池 0–200"的说法吻合（略高）。
2. 晋升答辩互动率 5.7% 已过第二阶 5% 门槛，第三轮hr 3.1% 只到全域平均。
3. **评论都是 0**——CES 里评论权重 ×4，这是当前最大的分数缺口。

⚠️ 发布 0 天的数据几乎全部来自初始推荐池，**搜索长尾还没开始进来**。
搜索流的价值要到 7 天后才看得出来。在那之前不要用这两行数据下任何结论。

## 三、预测模型 v1

### 输入

| 变量 | 来源 | 作用 |
|---|---|---|
| `density` | 词库.csv 竞争密度（低/中/高） | 该词能分到多少搜索流量、我们能不能排上去 |
| `median_likes` | probe_*.json 的 density.median_likes | 该词前排的量级，天花板参照 |
| `intent` | 词库.csv 意图强度 | 搜索意图越强，来的人越可能互动 |
| `audit_score` | 审核记录.csv 独立审核总分 | 对应搜索排名里 40% 的内容质量分 |
| `lane` | 搜索流 / 推荐流 | 切换整套系数 |

### 逻辑

**第一步：7 天观看量**

```
views_7d = base(density) × quality_factor(audit_score)
```

`base` 取值（搜索流）——低密度词竞争小排得上但盘子小，高密度词盘子大但排不上：

| density | base 区间 | 理由 |
|---|---|---|
| 低 | 250–600 | 前排中位数 ≤200 赞，说明这个词流量本身不大，但我们能占住位 |
| 中 | 350–900 | 有一定盘子，排名要靠内容质量争 |
| 高 | 200–700 | 盘子最大但前排被高赞占满，新号 7 天内难挤进前排，方差最大 |

`quality_factor`：审核分 ≥90 → 1.3；85–89 → 1.0；<85 → 0.7
（依据：内容质量在搜索排名里占 40%，是单项权重最高的）

**第二步：互动**

```
互动率 = base_rate(density, intent) × quality_factor
点赞 = 观看 × 互动率 × 点赞占比
```

搜索流互动分配（先验，待校准）：

| 项 | 相对点赞的比例 | 依据 |
|---|---|---|
| 收藏 | 0.6–1.0 | 搜索来的人是找答案的，收藏=存起来用。实测 5/9=0.56 |
| 评论 | 0.10–0.20 | 实测 0/9，评论最难拿，但 CES 权重 ×4，是最该争的 |
| 转发 | 0.08–0.15 | 实测 1/9=0.11 |

推荐流互动分配（先验）：收藏 0.3–0.5 · 评论 0.15 · 转发 0.08
（刷到就赞，收藏意愿低于搜索流）

**第三步：CES** 按官方公式算，关注数不预测（拿不到归因）。

### 输出形式：区间，不是点估计

样本量不足时给点估计是假精确。每项输出 `低-高` 区间 + 一个中位值，
复盘时判「实际值是否落在区间内」，而不是「差了多少」。

## 四、这个模型可以怎样被证伪

每条假设都对应一个可检验的预测，7 天后逐条对账：

1. 低密度词 7 天观看落在 250–600 → 若普遍低于 250，说明低密度词的搜索盘子被高估了
2. 收藏/点赞比 ≥0.6 → 若长期在 0.3–0.5，说明我们的内容不是"要存起来用"的类型，
   或者搜索流量根本没进来（查搜索来源占比即可分辨）
3. 审核分 90+ 的稿观看确实高于 85 分档 → 若无差异，说明审核分与真实表现不相关，
   整套打分体系需要重估（这条最关键，它检验的是审核标准本身）
4. 评论数 > 0 → 当前全 0。若加了具体提问式 CTA 后仍为 0，说明问题不在 CTA 设计

## 五、校准计划（T5）

- 发布满 7 天 → `fetch_stats.py` 回填 → `review_prediction.py` 自动对账
- 每次对账把「预测 vs 实际 + 偏差原因 + 系数调整」追加进 `xhs/素材库/预测复盘.md`
- 累计 ≥5 篇有 7 天数据后，才允许把先验系数改成拟合值。在那之前只调明显错的量级。
