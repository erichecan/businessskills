# 写稿策略进化路径

> 2026-09-13。起因：Eric 判断"写稿策略没有基于数据迭代，在重复生产没人看的笔记"。
> 本文档只写**查证过的事实**和**基于事实的下一步**，不写没数据支撑的猜测。

## 一、今天修复的三个数据管道断点

在能谈"怎么迭代"之前，先确认"感知"这一层本身是准的——三个断点，改之前都会让下面
第二节的结论完全算不出来或者算错：

| 断点 | 现象 | 根因 | 状态 |
|---|---|---|---|
| 机修队列死循环 | 5 篇稿子连续 7+ 天、每天 2 次运行各重试 2 次，结果和理由一字不差 | 机械项已经是"标题跟已发布的另一篇撞车"，但机修的 prompt 只改正文、从不碰标题，结构性地不可能修好 | 已修：加标题撞车专修通道 |
| 标题定向修改的偏移量 bug | 改完标题后文件结构被破坏（"## 发布标题"整行消失） | H1 替换后文本长度变了，却拿替换前算出的旧偏移量去切割新文本 | 已修：H1 替换后重新定位 |
| 审核校准的标题匹配断点 | 220 篇独立审核里只有 1 篇能匹配上真实发布数据 | 稿子在最后一次审核之后常被机修/标题档改一轮标题（改完不重审），审核记录存的是改之前的标题 | 已修：改用「发布日志→笔记链接→笔记ID」精确匹配，样本从 1 篇变 61 篇 |

同时去掉了"必须先探词验证才能选题"这道门槛（详见下方"选题机制"），改为
"候选/已验证都能选"+"写之前先比对是否跟自己已发布的东西撞车"。

## 二、第一次跑出来的真实结论（n=61，calibrate_audit.py）

以前这份报告从没真正生成过（可用样本永远是 1 篇，够不到 MIN_SAMPLE=8 的门槛）。
断点修复后第一次产出结论：

**1. 审核总分几乎不预测真实搜索表现**
总分 vs 搜索来源占比 秩相关 **+0.06**——现在决定"能不能发"的核心分数线（≥80 分），
本身跟"发出去搜索流量好不好"几乎没有关系。花 3 轮返工/机修把 79 分磨到 80+，
不能默认它会让这篇表现更好。

**2. "可信度"这条判据方向可能反了**
可信度 vs 搜索来源占比 **-0.48**（n=27，脚本自动标记"方向可疑"）——这条判据打得
越高，搜索进入反而越少。需要去 `skills/eric-xhs-audit/SKILL.md` 核对这条判据的
具体措辞，对照实际稿子看是不是判据本身站不住脚。

**3. 选题/标题预测"有没有人参与"，执行打磨类判据反而predict相反**
选题、标题 两个维度 vs 评论数：**+0.47 / +0.47**（正相关，n=61）；
首图、开头、正文、CTA 四个维度 vs 评论数：**-0.48 / -0.57 / -0.37 / -0.26**
（全部负相关）。也就是说：选对话题、起对标题，跟"有没有人愿意说句话"是同方向的；
但首图/开头/正文/CTA 这些"执行打磨"类判据打得越高，评论反而越少。**这跟
`tramstop-skill`（去AI味方法论）的核心判断吻合**——过度打磨、套路化的执行，
读起来更像AI，人味越少，互动意愿越低。这是一个**信号**，不是结论，下面第三节
第2步会说怎么把它坐实。

**4. 流量预测系数长期偏高，且"该调了"这个信号一直没被真正执行**
`预测复盘.md` 里几乎每一篇的结论都是"VIEWS_BASE 系数偏高，样本不够，再攒几篇"——
但直接去查 `预测校准.csv`，按密度分组的"观看"指标行数是 高33/低25/中19，
`predict.py` 自己的校准检查今天也打印过"样本已达16篇，可以考虑校准了"。
**"检测到该调"这个信号已经出现过，但没人真的去改 `VIEWS_BASE` 那行代码。**
这是本文档要指出的第二个"感知到了但没有行动"的断点，性质和"审核校准报告
从来没生成过"是一类问题：工具都在，触发条件也满足了，就是没有人/没有流程
把结论变成改动。

## 三、进化路径（分阶段，每阶段有明确的"证据够不够动手"判据）

延续这个仓库自己的纪律（`calibrate_audit.py` 头部写的三条）：**样本不够不下结论，
下结论了要么真的应用、要么明确记下"还差几篇"，不能停在"打印了一句提示"就算完事**。

### Phase 0 · 已完成（本次会话）
- 机修死循环 + 标题定向修改偏移量 bug（影响所有靠机修/标题档过线的稿子）
- 审核校准的笔记ID匹配（感知层修复，是后面所有阶段的前提）
- 场景标签持久化 + 关键词自身去重（选题层，防止选题继续偏斜同一批赛道）
- 去掉探词硬门槛，加"防自己撞车"机制

### Phase 1 · 立即可做（不需要新样本，现有数据就够）
1. **实际执行 VIEWS_BASE 重新校准**：不再等复盘文字里滞后的"样本不够"说法，
   直接看 `predict.py` 自己校准函数算出的当前样本数（高/低/中都已经过了 5 篇的
   老门槛），把 `VIEWS_BASE` 常量按 `预测校准.csv` 的实际中位倍数改一次。
   这是本文档写完之后第一个该做的动作，纯代码改动，随时能做。
2. **核实"可信度"判据**：拉 `审核校准报告.md` 逐篇明细里可信度打分高但
   搜索来源占比低的样本，对照 `skills/eric-xhs-audit/SKILL.md` 里这条判据的
   具体文字，判断是判据表述有问题还是巧合（n=27，中等把握，值得看但先别改）。

### Phase 2 · 需要做一次归因阅读（1-2 小时的人工/agent 工作，不需要新数据）
把"执行打磨类维度跟评论负相关"这个信号坐实：
- 用 `横向对比宽表.csv`（已经有结构化字段：审核分维度 + 发布表现）筛出两组稿子——
  首图/开头/正文/CTA 打分高但评论数是 0 的，和打分一般但评论数明显更高的。
- 逐篇对照读正文，判断差异具体落在哪（是不是签名句/"不是X是Y"这类AI味硬指标
  用得更密？是不是案例细节更假？），而不是停留在相关系数这一层。
- 归因结论如果站得住，去改 `eric-xhs-audit` 或知识框架里对应judge的权重/措辞，
  这是唯一一步**真正touch内容策略本身**（不是数字系数、不是流程bug）的动作。

### Phase 3 · 制度化（防止"有工具但没人跑"重演）
- 把 `calibrate_audit.py` + `review_prediction.py` 接进现有的定时任务链路
  （比如挂在 `xhs-health` 的周期任务里），固定节奏产出报告，而不是靠人偶尔手跑。
- 每次产出结论后，跑的人必须显式回答"应用了/为什么不应用/还差几篇"三选一，
  写进报告或 commit message——不能让"检测到了"停在打印一行字就结束，
  这正是 `VIEWS_BASE` 拖了这么久没调的原因。

### Phase 4 · 结构性调整（需要 Phase 1-3 攒出更大样本后再做）
- 现在"总分≥80 才能发"这道闸门经验证几乎不预测真实表现（+0.06），样本量
  更大之后应该重新评估：要不要把"选题/标题"这两个真正跟互动正相关的维度
  权重调高，把"执行打磨"类维度从"追求满分"降级成"及格线"（毕竟满分不预测
  好结果，过度打磨甚至可能是负担）。
- 这一步不在本次改动范围内——需要 Phase 1-2 先把样本和归因做扎实，
  按这个仓库自己的规矩，样本不够就不该动权重。

## 四、这次没有解决、但发现的另一个可能相关问题

这次的修法（笔记ID代替标题）核实一遍它的匹配率。
