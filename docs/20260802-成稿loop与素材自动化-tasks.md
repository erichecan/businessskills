      验收：跑一轮能完成 选题→成稿→机械检查→独立审核→(不过则返工)→落盘；
            返工必须换独立进程（不在同一会话自评自改）；
            轮次上限 3，仍不过写入 待激活素材库.csv；
            过线阈值 85（不是 90 —— 独立审核口径下 21 篇历史稿最高 86，定 90 会空转到上限）
      产出：scripts/xhs-loop/refine_loop.py
      依赖：T1
      进度：首跑跑通并暴露 4 个真问题，已全部修掉，正在复跑验证。
      首跑实测（选题「答辩PPT讲到一半被打断怎么办」）：
        第1轮 成稿→机械通过→独立审核 83 分（搜索意图仅 13/20：正文只出现 1 次「答辩」）
        第2轮 返工→机械通过→审核调用失败→**loop 读到上一轮的 83 分**
        第3轮 成稿输出解析失败→终止
        手动补审第2轮的稿：**89 分绿**，搜索意图 13→18。返工其实有效，是 loop 没读到。
      修掉的 4 个问题：
        ① audit() 只取「该文件最后一行审核记录」，不管本轮有没有写出新行 → 静默复用旧分。
           危险方向是反过来：上轮 90 分时审核失败会被读成过线，放行一篇没审过的稿。
           改成行数增量判断 + 内部重试 2 次，审不出来返回 None 而不是旧分。
        ② claude -p 失败即放弃 → 前面几轮的工全扔。加 run_claude() 重试 2 次（间隔 45s，
           连续 6 次 60k token 调用撞限流是常态），原始输出存 素材库/loop日志/ 供诊断。
        ③ pick_topic 要求「密度≠待探测」，比必须命中清单第 8 条还严（清单允许说明理由后赌）。
           结果 9 个已验证词里 7 个已写过、剩 2 个全是待探测 → 无题可做，把自己饿死。
           改成硬条件只留「状态=已验证」，密度未探测的排后面。
        ④ 缺渲染环节：89 分绿稿在发布闸门被判 ⛔「成品图目录没有已渲染的卡片图」。
           补 render_cards()，过线后自动调 make_cards.py。补渲染后闸门立刻转 ✅
           「独立审核 89分 · 处置发布 · 机械项通过 · 7 张图」——端到端链路自此打通。
        另修：headless claude 不知道今天几号，md 里「卡片见 图文_YYYY-MM-DD…」跨午夜必写错日期
              （首跑就指向了不存在的文件），save() 按实际落盘名校正 + prompt 里告知今天日期。
              短名改成固定用第一轮的，否则每轮换名会散落多份孤儿稿。
      复跑实测（选题「答辩ppt最后一页结束语」）：75 → 84 → 第3轮机械未过。
        验证了 audit 增量判断（三轮分数各不相同）、slug 固定（三轮同一文件）、返工有效（+9）、
        3 轮上限归档。**又暴露一个**：第 3 轮为改审核意见把具体名词密度从 2.0+ 改到 1.51，
        比第 2 轮更差，而 loop 只留最后一版 → 84 分那版被扔了。补两处：
        ⑤ 择优保留 + 结束时回滚到最佳版本。首版回滚条件写成 best.score > score，
           但机械未过的轮次 score 还留着上一轮的值（84 > 84 为假），回滚静默失效；
           改成直接比 md 内容。三场景模拟验证：越改越差→回滚 v2 ✓ / 过线→渲染收工不归档 ✓ /
           分数递增→不回滚 ✓
        ⑥ 返工 prompt 加 KEEP_PASSED：明确列出已达标的机械项，别为修一条意见改坏另一条。
        ⑦ park() 按既有约定把文件真的移进 归档稿/（原来只写 CSV，稿留在素材库根目录，
           health_check 每天会拿这篇「已决定不发」的稿报一次机械违规，纯噪音）。
      端到端验收（成稿_2026-08-03_答辩讲一半被打断.md）：
        独立审核 89 分绿 → 渲染 7 张卡片图 → auto_publish 闸门 ✅
        「独立审核 89分 · 处置发布 · 机械项通过 · 7 张图」——loop 产出的第一篇过闸门的稿。
