## 一、背景与目标

Eric（文彬）经常做两件高频且可复用的事：

1. 辅导学员修改简历、准备面试
2. 根据具体招聘信息给自己改简历

这套辅导有鲜明的个人方法论（不是通用简历技巧），权威来自 Eric 本人的背景：**前腾讯 12 年产品经理 + 现 AI 开发者**。目标是把这套方法论沉淀成一个可复用、可持续生长的 Claude Code skill，让 Eric 以「文彬教练」身份快速产出辅导成果。

### 方法论来源（两段真实辅导对话 + 一份自己的简历）

## 二、方法论签名（8 条，提炼自真实对话）

这是 skill 的灵魂，区别于任何通用简历工具：

1. **本质先行** —— 先讲清「招聘方到底在考察什么」。例：实习招聘不是看项目多深，而是看面试技巧、自我认知、行业认知、文化契合、好不好带。先揭开候选人看不见的考察标准。
2. **名词/缩写解码** —— 先把 JD 或简历里的专业术语、英文缩写（AI Infra、SIP、WebRTC…）全部讲透，让客户「会讲招聘方的语言」。
3. **判断模型 / 诊断模型** —— 用结构化模型诊断这个人，而不是给零散建议。
4. **做减法 + 1-2-3** —— 「信息有点多余了，要做减法」，核心讲清 3 点，其余作为这 3 点的支撑（why）。
5. **项目抽象成体验闭环 / 产品故事线** —— 例：三个充电项目 →「找得到 / 开得到 / 不用等」闭环。
6. **结合教练背书** —— 前腾讯 12 年产品 + 现 AI 开发经验，作为判断的权威来源。
7. **心理建设** —— 学员真问题常是「没自信、怕被深挖」，处理心理 + 揭开考察标准（呼应 eric-diagnosis「99% 是心理问题」）。
8. **JD 驱动的选择性强调** —— 从具体岗位出发，挑真正匹配的点重点打，不被一长串要求吓退。

## 六、全流程内部步骤（每步调对应知识包）

```
① 收集 & 解码  → 读客户信息/JD/简历，把所有英文缩写、专业术语先解码讲透
                 （调：简历改写范式 · 术语解码法）
② 诊断本质     → 揭示岗位/面试真实考察标准 + 客户 3 个核心焦虑
                 用判断模型分析（调：招聘本质与判断模型）→ 产出【诊断报告】
③ 改简历       → 项目抽象成体验闭环、选择性强调、JD 对齐、做减法 + 1-2-3
                 （调：简历改写范式）→ 产出【改后简历成稿】
④ 面试准备     → 预测深挖点 + 标准答法 + 心理建设
                 （调：面试准备范式）→ 产出【面试准备包】
⑤ （可选）可视化 → 说一声「出 HTML」，把简历/报告渲染成可截图的漂亮版本
```

## 七、三个交付物的硬约束（写进 SKILL.md）

- **诊断报告**：必须先讲**本质**（招聘方真实考察标准），再点客户**3 个核心焦虑**，最后给**判断模型**结论。做减法，1-2-3 讲清，拒绝零散建议。
- **改后简历**：Markdown 可复制；每段项目经历必须有「体验闭环 / 产品故事线」抽象；与目标 JD 显式对齐；不堆砌、不被 JD 长要求清单吓退，只打真正匹配的点。
- **面试准备包**：针对客户**具体焦虑**（如「怕被深挖细节」）；给「面试官会问什么 + 你怎么答 + 为什么这么答」；含心理建设（头脑清醒 > 项目深度）。
