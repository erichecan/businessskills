## 1. 背景与问题

现有 v1《面试咨询 IP 战略手册》方向正确——博商式"工业化生产 IP"的核心玩法（选题倒推、知识切片、赛马铺量、三级漏斗）已经讲清楚。但它停在**战略叙事层（道）**：告诉你"该这么干"，没告诉你"每一步具体怎么干、做到什么标准算合格、用什么数据判断、哪一步能交给 AI"。

用户诉求一句话：**"既然是工业化生产，就该有图纸、有检验标准、有数据标定，细化到工业级别，并用 AI 实现自动化、放大化。"**

本 spec 把 v1 从"战略手册"升级为"**生产图纸（Production Blueprint）**"——一份能照着施工的工业级文档。

---

## 2. 目标与非目标

### 目标
1. 产出一份端到端的"IP 工厂图纸"HTML 文档：总装图鸟瞰全产线 → 内容生产闭环画到最深 → 一路闭环到成交变现。
2. 每道工序有：作业标准（SOP）、检验标准（质量闸门）、数据标定（行业基准占位 + 待校准）、自动化路线（人主导 → AI 接管的演进路径）。
3. 每道工序的"自动化路线"对接**现有真实模块**（`skills/eric-*` / `app/` API），不空想。
4. 图纸的每张工序卡同时是**第二阶段施工的"系统模块说明书"**——图纸与系统无缝衔接。

### 非目标（本阶段不做）
- 不做可运行系统（那是第二阶段）。
- 不做多账号矩阵、多 IP 复制的产能机制（放大路径只做"单 IP 多产能 + 多平台分发"两条）。
- 不深挖交付车间内部 SOP（只在总图留接口 + 一道"案例沉淀"工序反哺选题）。
- 数据标定值不追求精确，先用行业经验基准占位，全部标【待校准】。

## 3. 核心理念：制造工厂隐喻

把 IP 生产当成一座真实工厂。整张图纸由统一的「**工序卡（Process Card）**」拼成，工序卡是全图纸的原子单元，也是未来系统的模块单元。

**执行主体模型**：初期**人主导**每道工序的判断与决策，后期 **AI 渐进接管**自动化。因此每道工序都带一条"自动化路线"，标清当前位置与升级路径。**永远人工**的工序（出镜、核心观点、1v1 成交）明确标注，不追求自动化。

**放大路径**（仅此两条，图纸为其设计产能机制）：
- **单 IP 多产能**：一个母体（一次咨询/一个观点）→ AI 切片放大成 N 条内容。
- **多平台分发**：一份内容自动适配小红书 / 抖音 / 视频号 / 公众号，一鱼多吃。

## 4. 工序卡模板规范（8 字段）

每张工序卡固定包含以下 8 个字段，缺一不可：

| # | 字段 | 说明 |
|---|------|------|
| ① | 工序号·名 | 内容车间 `P-C{n}`，变现车间 `P-M{n}`。如 `P-C4 切片放大` |
| ② | 输入物料 | 上一道工序的产出（明确的物料名） |
| ③ | 输出成品 | 交付给下一道的东西（明确的物料名） |
| ④ | 负责人 | 👤 人 / 🤖 AI / 👤🤖 协作（图标 + 当前主体） |
| ⑤ | 作业标准 SOP | 怎么做，3-5 步可执行动作 |
| ⑥ | 检验标准（质量闸门） | **合格判定** + **废品判定**；不达标拦下不流入下一道 |
| ⑦ | 数据标定 | 基准值【待校准】+ 计算公式 + 校准方式 |
| ⑧ | 自动化路线 | 当前 L 等级 → 目标 L 等级；用哪个 skill/app 模块升级 |

**自动化等级（L0-L3）定义：**
- **L0 纯人工**：人全程手做，无 AI 介入。
- **L1 AI 辅助**：AI 出草稿/建议，人逐条改定。
- **L2 AI 主导·人审**：AI 自动完成，人只抽检把关、放行。
- **L3 全自动**：AI 端到端自动执行，人不介入（仅看报表）。

## 6. L0 · 全厂总装图

一页鸟瞰整条产线，横向 6 个车间连成**闭环**：

```
选题 → 生产 → 分发 → 数据 → 私域 → 成交
  ↑                                    │
  └──────── 案例/数据反哺 ←────────────┘
```

每个车间方块显示三行：**输入→输出** / **关键标定值** / **当前自动化等级**。车间之间用箭头连接，数据与案例从尾部反哺回选题，形成自迭代闭环。

| 车间 | 输入→输出 | 关键标定值【待校准】 | 当前自动化 |
|------|-----------|---------------------|-----------|
| 选题 | 市场需求 → 选题清单 | 选题命中率 ≥ 30% | L1 |
| 生产 | 选题+母体 → 成品内容 | 单母体产出 ≥ 10 条 | L1→L2 |
| 分发 | 成品 → 多平台发布 | 覆盖 ≥ 3 平台 | L1→L2 |
| 数据 | 发布数据 → 爆款判定 | 爆款率 ≥ 5% | L2 |
| 私域 | 公域流量 → 意向用户 | 私信承接率 ≥ 80% | L0→L1 |
| 成交 | 意向 → 付费客户 | 付费转化 ≥ 5% | L0 |

## 7. L1 · 内容生产车间（7 张工序卡）

> 以下为每张卡的字段草案内容，HTML 渲染时即承载这些内容。标定值均为行业经验占位【待校准】。

### P-C1 选题立项
- **输入**：市场需求信号（评论区提问、竞品爆款、搜索词、咨询高频问题）
- **输出**：立项选题卡（含目标人群 + 痛点 + 预期钩子）
- **负责人**：🤖→👤审
- **SOP**：① 抓取面试垂类近 7 天数据 ② 按"痛点×搜索量×购买意愿"三交叉打分 ③ 只有三项都达标才立项 ④ 人工终审是否符合人设
- **检验**：合格＝三维度均过阈值且与"面试咨询"强相关；废品＝纯蹭热点、与变现无关、自嗨选题
- **数据标定**：选题命中率 ≥ 30%【待校准】｜命中率 = 带来询盘的选题数 / 立项选题数｜跑满 30 个选题后回填
- **自动化**：L1（现）→ L2｜`app:scrape` + `app:hot-topics` + `skills/eric-xhs-topic`

### P-C2 母体生产
- **输入**：立项选题卡
- **输出**：原始母体素材（一段出镜口播 / 一次真实咨询的洞察录音/文字）
- **负责人**：👤 **不可替代（永远 L0）**
- **SOP**：① 围绕选题口述核心观点（不写稿）② 带至少 1 个真实案例 ③ 录音或语音转文字留存
- **检验**：合格＝观点清晰 + 有真实案例 + 有"只有你能讲"的独特性；废品＝正确的废话、无案例、可被任何人替代
- **数据标定**：母体复用率 ≥ 8 条/母体【待校准】｜= 一个母体切出的成品数｜跑满 10 个母体后回填
- **自动化**：L0（永久人工）——这是你不可替代的价值源

### P-C3 脚本结构化
- **输入**：原始母体素材
- **输出**：结构化脚本（痛点场景开头 → 专业观点 → 案例佐证 → 行动指令）
- **负责人**：🤖→👤审
- **SOP**：① AI 把口述整理成四段式结构 ② 套用钩子公式强化开头 ③ 人工校正人设语气
- **检验**：合格＝四段齐全 + 开头 3 秒有钩子 + 行动指令明确；废品＝结构散、无钩子、AI 腔
- **数据标定**：脚本一次过审率 ≥ 70%【待校准】｜= 无需返工的脚本数 / 总数｜跑满 30 条后回填
- **自动化**：L1（现）→ L2｜`skills/eric-content` + `skills/eric-hook`

### P-C4 切片放大（单 IP 多产能）
- **输入**：结构化脚本 / 母体素材
- **输出**：N 条平台化笔记/视频脚本（**放大核心工序**）
- **负责人**：🤖
- **SOP**：① 把一个母体拆成多个角度（场景切片 / 人群切片 / 痛点切片）② 每个角度生成一条独立笔记 ③ 控制重复度避免同质
- **检验**：合格＝每条有独立钩子、不互相重复、单条可独立成立；废品＝换汤不换药、明显灌水
- **数据标定**：单母体产出 ≥ 10 条【待校准】｜= 成品数 / 母体数｜跑满 10 母体后回填
- **自动化**：L2｜`skills/eric-xhs-deconstruct` + `app:content`

### P-C5 成品制作
- **输入**：平台化笔记脚本
- **输出**：可发布成品（正文 + 标题 + 封面 + 排版，过 AI 味检测）
- **负责人**：🤖→👤审
- **SOP**：① 生成标题（钩子型）② 生成封面（保持 IP 视觉识别度）③ 排版 ④ 过 AI 味检测，超标重写
- **检验**：合格＝标题有钩子 + 封面有识别度 + AI 味检测通过；废品＝标题平淡 / 封面无辨识 / AI 味超标
- **数据标定**：AI 味检测通过率 ≥ 90%【待校准】｜= 通过条数 / 总条数｜跑满 50 条后回填
- **自动化**：L1（现）→ L2｜`skills/eric-xhs-title` + `skills/eric-xhs-cover` + `skills/eric-ai-check`

### P-C6 多平台分发
- **输入**：可发布成品
- **输出**：已发布内容（小红书 / 抖音 / 视频号 / 公众号）
- **负责人**：🤖
- **SOP**：① 按平台调性适配（标题长度、话题标签、封面比例）② 按内容日历排期 ③ 多平台同步/错峰发布
- **检验**：合格＝覆盖 ≥ 3 平台 + 每平台格式正确；废品＝一稿原样多投、格式错乱
- **数据标定**：平台覆盖 ≥ 3｜发布及时率 ≥ 95%【待校准】｜跑满 1 个内容日历周期后回填
- **自动化**：L1（现）→ L2｜`app:video` + 待开发"多平台适配器"

### P-C7 数据回收·反哺
- **输入**：各平台发布数据
- **输出**：爆款判定 + 复制指令 + 反哺选题清单
- **负责人**：🤖→👤审
- **SOP**：① 回收各平台数据 ② 按爆款阈值赛马筛选 ③ 爆款结构沉淀为模板、加投/复制 ④ 爆款主题反哺回 P-C1
- **检验**：合格＝每周产出爆款判定 + 至少 1 条可复制结论；废品＝只收数据不产结论
- **数据标定**：爆款率 ≥ 5%【待校准】｜爆款 = 24h 赞藏 ≥ 200（小爆）/ ≥ 1000（大爆）｜= 爆款数 / 发布数｜跑满 50 条后回填
- **自动化**：L2｜`app:stats` + `skills/eric-benchmark`

## 8. L2 · 变现车间（4 张工序卡）

### P-M1 私域承接
- **输入**：公域来的私信/评论意向
- **输出**：已承接 + 已分层标记的用户
- **负责人**：👤→AI 辅助
- **SOP**：① 第一条私信标准话术回复 ② 收集基本信息（岗位/阶段/痛点）③ 打标签分层（准付费 / 观望）
- **检验**：合格＝24h 内首响 + 已打标；废品＝漏回、未分层
- **数据标定**：私信承接率 ≥ 80%｜首响 < 24h【待校准】｜= 已回复数 / 总私信数
- **自动化**：L0（现）→ L1｜话术库 + 待开发"私信助手"

### P-M2 养熟转化
- **输入**：已分层意向用户
- **输出**：高意向待成交用户
- **负责人**：👤
- **SOP**：① 社群/朋友圈持续输出价值 ② 针对准付费用户定向跟进 ③ 用案例/限时名额制造转化节点
- **检验**：合格＝准付费用户有持续触达记录；废品＝养在池子里不动
- **数据标定**：意向→高意向转化 ≥ 20%【待校准】｜跑满 1 个转化周期后回填
- **自动化**：L0（现）→ L1（部分话术/SOP 可 AI 化）

### P-M3 成交
- **输入**：高意向用户
- **输出**：付费客户
- **负责人**：👤 **不可替代（永远 L0）**
- **SOP**：① 咨询前问卷筛匹配度 ② 首次沟通报价答疑 ③ 三级产品引导：¥99 简历诊断 → ¥999 模拟面试训练营 → ¥3000+ 全程 1v1 陪跑 ④ 跟进未付款
- **检验**：合格＝完成报价 + 明确成交/未成交结论；废品＝答疑后无跟进、丢单不复盘
- **数据标定**：付费转化 ≥ 5%（高客单）/ ≥ 15%（低价）【待校准】｜= 付费数 / 深度沟通数
- **自动化**：L0（永久人工，信任与成交不可替代）

### P-M4 案例沉淀（闭环反哺）
- **输入**：已交付客户的过程与结果
- **输出**：案例故事 → 反哺 P-C1 选题
- **负责人**：🤖→👤审
- **SOP**：① 交付后收集客户故事（脱敏）② 提炼成可传播案例 ③ 回灌选题库作为新母体素材
- **检验**：合格＝每个成交客户至少沉淀 1 个案例；废品＝交付完即结束、不留素材
- **数据标定**：案例转化率 ≥ 1 个/成交客户【待校准】
- **自动化**：L1→L2｜`skills/eric-report` + 知识库归档

## 12. 第二阶段接口预留（系统化）

本图纸即第二阶段施工蓝图。每张工序卡的字段直接映射为系统模块规格：
- 字段②③（输入/输出）→ 模块的数据契约
- 字段⑤（SOP）→ 模块的处理逻辑
- 字段⑥（检验）→ 模块的校验/质量闸门
- 字段⑦（标定）→ 模块的监控指标
- 字段⑧（自动化路线）→ 模块的实现优先级与对接的现有代码

第二阶段从"附录 C 标为'需开发'的缺口"切入（如多平台适配器、私信助手），逐工序把 L1 升级到 L2/L3。
