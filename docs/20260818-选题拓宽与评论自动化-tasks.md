对照七种力：结构力/说服力有量，**示弱力、边界力、反馈力、化解力、破冰力几乎零对应词**。

根因是系统里**没有「场景」和「概念」这两个维度**。现有链路
`种子词 → 采集 → 词库（纯字符串）→ probe → pick_topic（按搜索位强度贪心）`
全程只认关键词字符串，于是：

1. **去重只能按字符串** —— 「HR问"你的缺点"该怎么回答」有 4 个变体词同时在已验证里，
   闸门「同词最多 2 篇」完全拦不住「同话题换个词串」。这就是感觉到的重复。
2. **没有覆盖度度量** —— 没有任何环节会说「边界力零产出」，偏斜可以一路滚下去。
3. **`pick_topic()` 是贪心的** —— 谁搜索位强写谁，而强的都在面试赛道（历史采集偏面试），
   它天然让偏斜自我强化。

`20260816-职场表达场景版图.md` 那次扩展（种子池 4→9）方向对，但只动了最上游的种子，
新词还堵在采集→验证的漏斗里，下游选词仍然只认「搜索位强度」这一把尺。

### 一个必须一起看的事实

已回填的搜索来源占比：3.3% / 1.3% / 1% / 2.6% / **45.3%** —— 除一篇外流量基本不是搜来的。

**本轮把这把尺从「全局门槛」降级为「格子内排序」，就是冲着这个事实去的。**

## S3 `pick_topic()` 改配额驱动 + 去重升级
- [x] 完成 · 三条验收全过：连续 5 次选题落在 **4 个不同场景**（旧版会连选 4 次同一个）；
      超额场景「向上汇报」（近 14 天 29 篇 / 目标 4）**不再被选中**且不报无题可做；
      pool 为空时正确返回 None

### 实现要点
- 缺口 = `周目标篇数 × 14/7 − 近14天产出 − 本进程已选`。**缺口 ≤ 0 就跳过，这就是新的去重闸** ——
  一个参数同时当配额和上限，不用再维护第二套「同场景最多 N 篇」的规则。
- 搜索位强度从**全局门槛**降级为**格子内排序键**。冲着「已回填的搜索来源占比除一篇外都在 1–3%」
  去的：流量基本不是搜来的，拿它当全局硬门槛正在拦掉整片非面试场景。
- 三重不饿死保护（这个函数已经把自己饿死过两次）：某场景没词 → 记缺词信号后跳下一个；
  只剩弱词 → 同上；所有缺口场景都没词 → 退回旧的全局最强。
  只有「全局最强也 < MIN_SLOT_STRENGTH」才真的不写（2026-08-14 那条停手仍有效）。

### 两个只有跑起来才会发现的坑
1. **同一进程内连选同一格子**。`scene_output()` 靠扫成稿文件算产出，写盘前缺口不变，
   5 次调用有 4 次都选了「年终述职」。加 `_PICKED_THIS_RUN` 扣减。
   ⛔ 不能指望「save() 写完盘下次就对了」—— dry-run 和写稿失败都不写盘。
2. **缺词信号重复刷屏**。pick_topic 每次都遍历全部缺口场景，无词的每个记一条，
   5 次调用写出 15 行、8 行一模一样。改成按（日期 × 场景）去重 ——
   不改的话 S4 会把定向种子词的配额全砸在同一个场景上。

### 打标 tie 的隐式依赖（顺带修掉）
「晋升述职 业务理解板块」同时命中「述职」(年终述职) 和「晋升」(晋升答辩)，**长度相同**，
旧实现靠遍历顺序 = CSV 行序决定归属 —— 往表里插一行就可能悄悄改掉一批词的归属。
改法两条：`tag()` 同长度时按场景名字典序做**确定性** tie-break；给晋升答辩加特异长词「晋升述职」。
另加 `scene_map.ties()` 用来查还有哪些词是并列命中的。
- **改法**（`scripts/xhs-loop/refine_loop.py`）：
  ```
  ① 算每个（场景 × 概念）格子近 14 天产出数 vs 周目标
  ② 缺口最大的格子优先
  ③ 格子内再按现有搜索位强度排序挑词（强度降级为格子内排序，不再是全局门槛）
  ④ 格子里没有可用词 → 写一条「缺词信号」进台账，交给 S4
  ⑤ 所有格子都无词 → 退回现有全局最强逻辑
  ```
  去重同步升级：现在是「同关键词最多 2 篇」，改成「同（场景 × 概念）近 14 天最多 N 篇」。
- ⛔ **第 ⑤ 条不能省**。`pick_topic` 的注释里已经记着两次「把自己饿死」的前科
  （初版把竞争密度当硬条件、08-14 那次强度硬拦），配额是软约束，不许变成新的死闸。
- **验收**：
  1. 连续 5 次调用 `pick_topic()`，选出的词落在 ≥3 个不同（场景 × 概念）格子
  2. 构造用例：某格子已达上限 → 该格子的词不再被选中，且不报「无题可做」
  3. 全部格子无词的极端用例 → 仍能返回一个词并打印告警，不返回 None
- **产出**：`scripts/xhs-loop/refine_loop.py`
- **依赖**：S2

## S4 采集种子词由缺口驱动
- [x] 完成 · 两条验收全过：缺口场景「拒绝不合理任务」的模板词进了投放清单且**总投放量仍是 8**；
      近 3 轮命中率全 <40% 的定向词自动停投，新词（无命中记录）不被误伤

### 实现要点
- **缺口词占 GAP_N=2 个种子名额，不加量**。采集每词一次搜索抓取是有成本的，
  补场景该靠把名额从饱和的种子上挪走（那 4 个跑了 170+ 次、命中率掉到 0 的词），不该靠加量。
- 池里没有的模板词会**真的 append 进 pool** —— 只 return 不 append 的话，
  `update_pool()` 的 `by_kw.get(kw)` 找不到它就 `continue`，这个词跑完什么成绩都不留。
- 只认最近 7 天的缺口信号；同一场景取最新一条。
- ⛔ 缺口驱动是**加权不是替换排序**：如果变成主排序，同一个空场景会被反复投到饱和 ——
  而它之所以空，往往正是因为这个词本身搜不出东西。
- **改法**：`daily_collect.pick_keywords()` 在现有轮换基础上，读 S3 写出的「缺词信号」，
  把缺口场景经「关键词模板」翻成定向种子词优先投放。
- ⛔ 保留现有的「按最近运行升序轮换」（`20260816` 那次修的 bug，种子无序切片导致新种子永不投放）。
  缺口驱动是**加权**，不是替换排序 —— 否则同一个空格子会被反复投到饱和。
- **验收**：
  1. 人为制造一个空格子（如「边界力 × 拒绝不合理任务」），下一轮 `daily_collect` 的投放清单里出现对应种子
  2. 该轮命中率记进关键词池；连续 3 轮命中率 <40% 的定向种子自动降权（沿用泛词串场的既有教训）
- **产出**：`scripts/xhs-collect/daily_collect.py`
- **依赖**：S3

### 三个跑起来才发现的问题
1. **用户名全空**：条目里有两个 `a[href^="/user/profile"]`，第一个是头像链接、textContent 是空的。
2. **回复框认错人**（最险的一个）：第一条填完框不会自己关，第二条点「回复」时
   placeholder 还写着上一个人的名字。**dry-run 第一次就撞上了** ——
   要回给「👼」的话，框是「回复 不妄」的。靠 placeholder 回读拦住了，
   但拦住只是不发、链路仍然断的，根治是每条回复前重新加载通知页。
   ⛔ 这道回读校验不许省：把话回到陌生人的评论下，比不回严重得多。
3. **字母型评论把模型问懵**：有位读者回了「A」—— 那是首评 CTA 的兑现请求，
   而普通回复 prompt 遇到「A」只会说「没有具体信息，没法引用细节」，等于当着读者的面失信。
   加了 `LETTER_RE` + 专门的 prompt：先兑现，认不出是哪篇笔记的选项时**只追问、不瞎编**。

### 顺带补的一条内容约束
读者说「偷偷做仪式扎他，他现在经常请病假」，模型回的是
「这招你还真敢用，他请假频率是每周还是隔阵子一次」—— **追问细节等于表态认同**，
而账号人设是职场表达不是陪聊诅咒同事。prompt 加了「不要顺着对方的做法往下聊」。
改后同一条重新生成：「怂到不敢正面说，这个感受挺真实的，那如果不硬钢，
你有没有想过用什么话把当面的事说出来？」——拉回真处境。

### 已知缺口：回复战场的存活校验做不了
通知页拿不到笔记链接（条目里的 a 全指向评论者主页），`opencli comments` 又要求
带 xsec_token 的完整 URL，`creator-notes` 在这个 profile 下返回空。
所以「发出 1 小时后回查还在不在」这条对**回复**这一战场暂时无解。
可用的替代信号：下次 `watch` 时如果我回复过的那条评论从列表里消失了，
说明整条被删/被折叠。⚠️ 这条还没实现，留给下一轮。
- **改法**：先跑 `watch --probe` 在**真页面**上定选择器，再填 `COMMENT_SELECTORS`，
  然后接自动回复（每条评论只回一次）。
- ⛔ 脚本注释里已经写死这条纪律：不先 probe 就凭空写选择器 = 抓到 0 条和「本来就没有新评论」

### 风控层单测结果
| 项 | 结果 |
|---|---|
| 今日 12 条上限 | ✅ 拦 |

**去同质的度量是实测选的**：3-gram Jaccard 把「那句原话 / 的那句话」这种改写的差异
