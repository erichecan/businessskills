# eric-xhs-probe：搜索位空缺探测

你的任务是回答一个问题：**这个搜索位，还有没有空缺。**

不是拆爆款。不分析别人的内容结构。依据 `docs/20260731-搜索流转向决策与实施方案.md` 决策 5——
抓别人笔记只抓：关键词、标题句式、评论区用户原话、前排答案空缺，**不抓内容本身**。

---

## 三层架构中你的位置

```
probe.py（客观提取，已完成）  →  【你在这里：判断】  →  backfill.py（回填，脚本执行）
```

**你不联网。** 所有数据已在 JSON 里。需要新数据就让用户先跑 probe.py。

---

## Step 1：读取探测结果

```
xhs/素材库/探测原始/probe_<YYYYMMDD>_<关键词>.json
```

用户没指定就读当天所有 `probe_*.json`。每个文件的关键字段：

| 字段 | 含义 |
|---|---|
| `completeness` | `full`(含评论) / `partial`(仅笔记) / `failed` |
| `_error` | 有值说明中断原因，`captcha_triggered` = 被安全验证拦截 |
| `top_notes[]` | 前排笔记：rank / title / author / likes / published_at / url |
| `comments[]` | 评论原话（已剥元数据、已滤作者自评论） |
| `density` | **脚本按确定性规则算出的竞争密度，你不得推翻** |

`completeness != full` 时，在输出开头注明数据完整度，分析照做但标注置信度。
`_error == "captcha_triggered"` 时，**只报告不分析**——数据不足以判断，让用户稍后 `--resume`。

## Step 2：五段分析

### ① 竞争密度回执（复述，不重判）

脚本已给出 verdict 和 reason，你只做三件事：
1. 复述 `density.verdict` 和 `reason` 里的原始数值
2. 给一句话处置建议：**做 / 缓 / 放弃**
3. `verdict == "待探测"` 时，说明缺哪个维度、需要补什么

> ⚠️ 阈值仍在校准期（`rule_version` 见 JSON）。**校准完成前，不得仅凭 verdict=高 就判「放弃」**，
> 必须结合②的答案空缺一起看：密度高但空缺明显的词仍然可做。

实测口径说明（与原方案不同，2026-08-02 修正）：
- 小红书网页端**不提供笔记总数**，所以「笔记数不多」这条改用**前排点赞分布**代理：
  前排混着大量低赞笔记 = 搜索位没被占满。
- **下拉补全取不到**（合成事件被防护），改用**标题精确匹配率**代理：
  匹配率低 = 没有笔记正面回答这个长句 = 空缺信号。

### ② 答案空缺（本框架唯一的核心判断）

读 `top_notes` 的标题 + `comments`，回答两问：

**a. 前排都在给什么答案** — 归类，不超过 4 类，每类标出对应的 rank。

**b. 没人给的是什么** — 必须具体到「**哪种处境的人没被回答**」。

禁止这类空话：
- ❌「内容不够深入」「缺少实操案例」「没有针对性」
- ✅「前排都在讲空降后怎么立威，没人讲**立威之后下属照样阳奉阴违该怎么办**」

**c. 交叉验证** — 评论区有没有人在追问前排没答的东西？
- 有 → 标注「空缺证据强」，并引用那条原话
- 无 → 标注「空缺为推断，证据弱」

> 评论里的**负反馈**价值最高——「照做了但没用」「我们公司不是这样」这类，
> 直接暴露前排答案的失效边界，是空缺的最硬证据。

### ③ 标题句式提取

只提取**句式骨架**，剥离具体内容。

- ✅「被X问倒怎么办」「X的三个瞬间」「前N天不做这事，迟早被Y」
- ❌ 摘抄完整标题

同一句式在前排出现 ≥3 次的，标注「已饱和」——说明这个壳子读者已经看腻。

### ④ 评论区原话筛选

从 `comments` 中筛出符合决策 6「真话是短的糙的不完整的」的条目。

**筛入标准**（满足任一）：
- 描述了具体处境（时间、场合、对方身份、具体的话）
- 表达了失效反馈（照做没用、不适用）
- 带情绪但指向具体事件

**排除**：纯感谢（「干货！谢谢老师」）、纯表态（「学到了」）、引流、广告。

按 `xhs/素材库/评论区原话.csv` 的现有 5 列输出：

| 列 | 要求 |
|---|---|
| 日期 | 探测日期 |
| 来源链接 | `comments[].note_url` |
| 用户原话 | **逐字保留**，含错别字、繁体、口语，不润色不断句 |
| 暴露的处境 | 写具体处境，不写情绪标签（❌「焦虑」✅「空降后下属阳奉阴违」） |
| 候选词 | 从这条原话反推出的新长尾词，没有就留空 |

### ⑤ 意图强度与场景类型

按词库既有取值填，各写一行判据：

- **意图强度** `高/中/低` — 搜这个词的人离行动有多近。「明天就要用」= 高。
- **场景类型** `事件/情境/症状` — 事件=一次性节点（答辩/面试）；情境=持续状态（空降前30天）；症状=反复出现的困扰（汇报被打断）。

## Step 3：输出

### 3.1 对话里给人类可读摘要

每个词一段，控制在 6 行内：

```
【关键词】
密度：低（前排中位数 66 赞，低赞占比 70%）→ 做
空缺：前排都在讲怎么立威，没人讲立威后下属照样阳奉阴违怎么办（评论区有人直接反馈「说了，该欺负你的还是照常欺负」— 证据强）
句式：「前N天不做这事，迟早被X」已饱和 ×3
原话：3 条入库，2 条带新候选词
```

### 3.2 落盘结构化结果

写 `xhs/素材库/探测原始/probe_<date>_<slug>.result.json`：

```jsonc
{
  "keyword": "...",
  "analyzed_at": "2026-08-02T15:20:00",
  "density_echo": "低",
  "disposition": "做",              // 做 | 缓 | 放弃
  "gap": {
    "existing_answers": ["前排答案分类1", "..."],
    "missing": "哪种处境的人没被回答（一句话，具体）",
    "evidence": "strong | weak",
    "evidence_quote": "支撑的评论原话，无则 null"
  },
  "title_patterns": [{ "pattern": "前N天不做这事，迟早被X", "count": 3, "saturated": true }],
  "quotes": [
    { "日期": "2026-08-02", "来源链接": "https://...", "用户原话": "逐字",
      "暴露的处境": "...", "候选词": "..." }
  ],
  "intent": "高",
  "scene_type": "情境",
  "judgment_note": "意图与场景的判据各一行"
}
```

字段与 `backfill.py` 一一对应，**不要增删字段名**。

## 数据不足时

| 情况 | 做法 |
|---|---|
| `completeness == "partial"`（无评论） | 照常做①②③⑤，④跳过并注明「无评论数据，原话库本轮无产出」；②的证据强度自动降为 weak |
| `completeness == "failed"` | 只报告，不分析 |
| `_error == "captcha_triggered"` | 只报告，提示用户稍后 `python3 scripts/xhs-probe/probe.py --resume` |
| `top_notes` < 8 条 | density 会是「待探测」，②照做但注明样本不足 |
